-------------------------------------------------------------------------
Analysis
-------------------------------------------------------------------------
1. trap_illegal_instruction @ 0x80000094
   Occurs during early boot/reset setup, before the add test body runs.
   riscv-tests' startup harness probes for optional ISA extensions by
   executing an instruction and catching the resulting illegal-instruction
   trap when unsupported. Expected boot-time behavior, not a fault caused
   by the add instruction itself.

2. trap_instruction_page_fault @ 0x2a14 (x2, same epc)
   This is the actual virtual-memory page fault relevant to the task.
   First fetch of the instruction at 0x2a14 misses the page table, Spike's
   fault handler installs the mapping for that page (demand paging), and
   execution retries the same instruction -- hence the identical epc on
   both lines. This confirms v-mode paging is active and being exercised
   during the add.S test.

3. trap_user_ecall @ 0x2f1c
   Final ECALL from the test harness to report PASS/FAIL and exit cleanly.
   Confirms the test ran to completion.

-------------------------------------------------------------------------
Conclusion
-------------------------------------------------------------------------
rv64ui-v-add completed successfully under Spike in virtual mode. One
genuine instruction page fault was observed (at epc 0x2a14, triggered
twice due to the fault-then-retry sequence), consistent with normal
demand-paging behavior on first access to a code page. No unexpected
or unhandled faults occurred.
